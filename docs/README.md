## Глоссарий

| Термин | Значение |
|---|---|
| Мероприятие, событие | `SportEvent` в event-service. Карточка в афише |
| Направление | Вид спорта, `SportType`. Справочник пополняется пользователями («своё направление») |
| Запись | `Registration`. В режиме `FREE` сразу `APPROVED`, в режиме `BY_APPLICATION` создаётся как `PENDING` |
| Заявка | Запись в статусе `PENDING`, ждёт решения организатора |
| Организация, клуб | `Organization` в identity-service. Привязана к аккаунту с ролью `ORGANIZATION` через `owner_user_id` |
| Допуск | Одобрение организации администратором (`APPROVED`). Без допуска клуб не публикует события |
| Вердикт ИИ | `AiVerdict`: `AI_APPROVED` или `FLAGGED` плюс возрастная метка `CHILD_SAFE` или `ADULT_ONLY` |
| Премодерация пользователя | Любое новое мероприятие частного пользователя создаётся в `ON_REVIEW` и в афише не появляется, пока администратор не нажмёт «Подтвердить», независимо от вердикта ИИ |
| Придержка (hold) | Флаг в вердикте: `hold = flagged && autoHoldFlagged`. На статус влияет только вместе с правилами `EventService.applyVerdict`; для пользователей афиша закрыта и без `FLAGGED` |
| Хранитель качества | Агент в ai-moderation-service: эвристика, LLM, подсказки `AgentSuggestion`, авто-снятие опубликованного события при смене вердикта на `FLAGGED` |
| Куратор справочника | Логика в event-service (`SportCuratorService`): подсказки, заявки на новый вид, метрики и предложения слияния для админки |
| Снятие с публикации | Перевод события в `UNPUBLISHED` с обязательной причиной |
| Журнал | `ModerationAction`: лог всех ручных решений администратора |
| Демо-аккаунт | Аккаунт с `demo = true`, выбирается без пароля. Id зафиксированы в `DemoIds` |

## Как поддерживать

- Меняете бизнес-правило — обновите [domain-rules.md](domain-rules.md). Источник истины всё равно код, документ должен с ним совпадать.
- Добавляете сервис, межсервисный вызов или переменную окружения — обновите [architecture.md](architecture.md) и таблицу переменных в корневом README.
- Принимаете решение, которое потом придётся объяснять, — допишите запись в [decisions.md](decisions.md).
- Нашли проблему, которую не чините сейчас, — добавьте её в [known-issues.md](known-issues.md).
