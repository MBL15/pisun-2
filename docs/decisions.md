# Архитектурные решения

Короткие записи: что решили, почему и чем за это платим. Новые решения добавляйте в конец.

## 1. Микросервисы на одном репозитории и одной базе

**Решение.** Пять Spring Boot-сервисов и общий `common-lib` в одном Maven-проекте. База физически одна (`sportdb`), но таблицы разделены по сервисам, а внешних ключей между сервисами нет.

**Почему.** Кейс требовал показать сервисную архитектуру, но запуск должен оставаться простым: один скрипт, одна H2 или один PostgreSQL.

**Цена.** Изоляция данных держится на дисциплине, а не на инфраструктуре. Целостность ссылок между сервисами никто не проверяет.

## 2. Имитация авторизации заголовками

**Решение.** Фронтенд передаёт `X-User-Id` и `X-User-Role`, сервисы доверяют им и сами проверяют права на уровне бизнес-логики.

**Почему.** На хакатоне жюри должно переключать роли в один клик, без паролей.

**Цена.** Любой может подделать заголовки. Для продакшена шлюз должен проверять токен (JWT или OAuth2) и сам выставлять `X-User-*`, срезая пришедшие от клиента. Код сервисов при этом менять не придётся: они уже работают через `CurrentUser`.

## 3. Внутренние эндпоинты `/internal/**` без проверки прав

**Решение.** Изменения, которые инициирует модерация, идут через `/internal/**` профильного сервиса. Проверка администратора делается в ai-moderation-service.

**Почему.** Сервис-владелец данных меняет их сам, а модерация собрана в одном месте и пишет журнал.

**Цена.** Защита держится на том, что шлюз не публикует `/internal`. См. [known-issues.md](known-issues.md).

## 4. Модерация не блокирует публикацию

**Решение.** Если ai-moderation-service недоступен, event-service публикует событие с вердиктом `FALLBACK`.

**Почему.** Недоступность вспомогательного сервиса не должна ломать основной сценарий.

**Цена.** В момент сбоя событие может попасть в афишу без проверки и с меткой `CHILD_SAFE`. Метка выставляется так, если аудитория не «Взрослые». Администратор видит `FALLBACK` в сводке события.

## 5. Эвристика как обязательный слой, LLM — опциональный

**Решение.** Встроенный анализатор на регулярных выражениях работает всегда. LLM подключается ключом, результаты объединяются по принципу «строже из двух».

**Почему.** Проверка должна гарантированно работать на любой машине без ключей и интернета. LLM добавляет понимание контекста, если она есть.

**Цена.** Регулярные выражения дают ложные срабатывания и пропуски, их нужно поддерживать вручную.

## 6. Допущенные организации публикуют без премодерации

**Решение.** Придержка `ON_REVIEW` применяется только к событиям частных пользователей.

**Почему.** Организация уже прошла ручную проверку администратором. Задерживать её события — лишнее трение.

**Цена.** Нарушение в событии клуба видно в афише, пока администратор не снимет его по сигналу ИИ.

## 7. Документы — HTML, PDF через печать браузера

**Решение.** doc-generator-service отдаёт HTML-страницу A4 с кнопкой печати. Серверного рендеринга PDF нет.

**Почему.** Нет тяжёлых зависимостей, шаблоны редактируются как обычный HTML прямо в админке.

**Цена.** Вид PDF зависит от браузера пользователя.

## 8. Схема БД от Hibernate

**Решение.** `ddl-auto: update`, без Flyway или Liquibase.

**Почему.** Скорость разработки прототипа.

**Цена.** Переименования и удаления колонок не применяются, а миграции данных невозможны. Перед продакшеном нужно ввести миграции.
